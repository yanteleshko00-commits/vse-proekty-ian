# Все проекты #Ian — версия 3.1

Генератор полного комплекта школьного индивидуального проекта.

## Что создаётся

- Текст индивидуального проекта: проблема, цель, задачи, теория, практика, заключение и источники.
- Презентация в PPTX и PDF.
- Проектный продукт: буклет, памятка, чек-лист или мини-гайд (PDF и PNG).
- Текст выступления для защиты и вопросы комиссии (PDF).
- ZIP-архив со всеми успешно созданными файлами.

## Несколько ИИ-провайдеров

Сервер запускает все настроенные текстовые ИИ-провайдеры параллельно, проверяет полученные JSON-ответы и выбирает наиболее качественный прошедший проверку вариант. Если один провайдер недоступен, остальные продолжают работу. OpenRouter при несовместимости JSON-режима делает повторный запрос без этого ограничения, после чего JSON всё равно проверяется сервером. Если ни один не вернул корректный ответ, сервер показывает безопасную диагностику по каждому сервису без раскрытия API-ключей.

Поддерживаемые переменные окружения:

| Переменная | Провайдер |
|---|---|
| `GEMINI_API_KEY` | Google Gemini |
| `OPENROUTER_API_KEY` | OpenRouter Free |
| `GROQ_API_KEY` | Groq |
| `DEEPSEEK_API_KEY` | DeepSeek |
| `MISTRAL_API_KEY` | Mistral |
| `ANTHROPIC_API_KEY` | Anthropic Claude |
| `CLOUDFLARE_ACCOUNT_ID` + `CLOUDFLARE_API_TOKEN` | Cloudflare Workers AI |
| `OPENAI_API_KEY` | OpenAI |

Чтобы сравнение работало между несколькими сервисами, добавь в Render ключи как минимум двух провайдеров. Бесплатные тарифы и лимиты устанавливают сами поставщики; наличие ключа не гарантирует постоянную бесплатную доступность.

Дополнительные параметры:
- `GEMINI_MODEL` — модель Gemini (по умолчанию задаётся сервером).
- `GROQ_MODEL` — модель Groq.
- `DEEPSEEK_MODEL` — модель DeepSeek (по умолчанию `deepseek-flash`).
- `MISTRAL_MODEL` — модель Mistral (по умолчанию `mistral-small-latest`).
- `ANTHROPIC_MODEL` — модель Claude (по умолчанию `claude-sonnet-5-5`).
- `OPENROUTER_MODEL` — маршрут/модель OpenRouter (по умолчанию `openrouter/free`).
- `CLOUDFLARE_AI_MODEL` — модель Cloudflare Workers AI.
- `OPENAI_IMAGE_MODEL` — модель генерации изображений, если включена.
- `ENABLE_AI_IMAGE_GENERATION=true` — включает генерацию изображений там, где она поддерживается кодом.
- `GENERATION_TIMEOUT_MS` — общий лимит ожидания генерации.

## WordyBot

В репозитории нет подтверждённого официального API WordyBot. Его публичные страницы описывают генерацию плана и дальнейшую работу в личном кабинете, но не публикуют API-документацию для сторонней интеграции. Поэтому сервер не имитирует вход в чужой аккаунт и не автоматизирует закрытый интерфейс. Подключать WordyBot можно после получения от сервиса официальной API-документации и разрешения на интеграцию.

## Сохранение и восстановление задач на бесплатном Render

Для обычной работы платный Persistent Disk не требуется. По умолчанию сервер использует временный каталог операционной системы (`os.tmpdir()`) и сохраняет туда контрольные точки генерации.

Что сохраняется по ходу работы:
- текстовая основа проекта;
- готовый итоговый продукт и его PNG;
- план презентации;
- речь для защиты;
- готовые файлы по мере завершения их сборки (PPTX, PDF, DOCX, PNG и ZIP).

Каждый готовый файл записывается отдельным бинарным файлом, а JSON-задача хранит контрольную точку, текущий этап и список доступных материалов. Запрос `GET /api/generation-jobs/:id` возвращает:
- `checkpoint` — последний полностью сохранённый этап и его данные;
- `partialFiles` — уже созданные файлы, если генерация ещё не завершилась;
- `result` — полный комплект после успешного завершения.

Если процесс перезапустился, но временные файлы ещё доступны, задача при следующем запросе будет помечена как `interrupted`. Последняя контрольная точка и сохранённые файлы останутся доступны через тот же endpoint. Запрос к нейросети автоматически не продолжается с середины: безопаснее повторно запустить генерацию, чтобы не получить дубли или несогласованные материалы.

**Ограничение бесплатного тарифа:** временная файловая система не является постоянным хранилищем. Новый Deploy, перезапуск/замена инстанса или очистка файловой системы могут удалить контрольные точки и файлы. Поэтому восстановление после таких событий работает по принципу best effort, без гарантии сохранности. Это бесплатный вариант без покупки диска.

Старые задачи и их временные файлы очищаются примерно через 24 часа после последнего обновления, если процесс успевает выполнить очистку.

## Запуск локально

1. `npm install`
2. Скопируй `.env.example` в `.env` и добавь собственные API-ключи.
3. `npm start`

Для Render добавляй переменные в **Environment**. Не помещай настоящие ключи в GitHub и не отправляй их в чат.

## Проверка

- `GET /api/health` показывает список провайдеров, ключи которых обнаружены сервером.
- `POST /api/generate-project/start` запускает фоновую генерацию.
- `GET /api/generation-jobs/:id` возвращает состояние задачи и готовые файлы.
