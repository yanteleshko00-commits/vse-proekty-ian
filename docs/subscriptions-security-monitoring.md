# Unified NEXORA account, protection and monitoring

NEXORA ID is the authoritative database. Existing packages remain unchanged (200 RUB / 3, 500 RUB / 5, 1000 RUB / 10 credits). Existing active administrator-assigned subscriptions are honored until expiration. Registered generations are reserved centrally; failed operations are refunded, and the shared account limits are 30 attempts/hour and 4 concurrent reservations. Guests retain separate local rate limits. Paid subscription checkout/auto-renewal is not enabled by this change. Text and Math use optional OAuth through the configured lobby and existing bridge keys; users can still work without signing in. Existing image and project flows remain. No new credentials are required if bridges and OAuth are already correctly configured.

Each app instance has bounded HTTP admission (48 in-flight requests, 8 simultaneous write requests by default), per-IP rate limits and cross-site write filtering, request size caps and existing generation-specific limits. This is application protection, not a network-level DDoS guarantee. Health endpoints do not run paid AI requests. The scheduled GitHub Actions monitor checks eight endpoints every ten minutes, best effort; GitHub may delay cron runs. Failed or degraded checks are shown in the workflow summary. The developer console reads service health and available protection counters. Tests cover the shared account policy in the auth repo and HTTP guard, studio-ticket binding, and application suites in this repo. Production auth and provider behavior require live credentials and separate verification.
