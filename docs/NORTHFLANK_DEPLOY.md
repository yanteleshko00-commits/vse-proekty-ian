# Развёртывание на Northflank

Эта инструкция описывает предварительный тестовый деплой. Условия Northflank требуют, чтобы пользователь был не младше 16 лет и не являлся несовершеннолетним по законам своей страны проживания, а также имел правоспособность заключать соглашение. Поэтому несовершеннолетний не должен создавать аккаунт, указывать фиктивный возраст или управлять оплатой через чужие данные. Родитель или другой законный взрослый может самостоятельно решить, брать ли на себя владение аккаунтом, договор и биллинг, соблюдая правила сервиса и местное законодательство. Источник: https://northflank.com/legal/terms.

## Текущая готовность

- Приложение собирается из корневого Dockerfile.
- Контейнер слушает `0.0.0.0:3000`.
- Проверка состояния: `GET /api/health`.
- Каталог заданий и артефактов: `/app/data/generation-jobs`.
- GitHub Actions собирает образ, запускает контейнер с тестовым Docker volume и проверяет сохранение файла после пересоздания контейнера.
- Эта ветка `deploy/container-ready` предназначена для предварительного теста. Production на Render не затрагивается.

## Создание тестового сервиса

1. Владелец сервиса создаёт проект `vse-proekty-ian`.
2. Создаёт сервис типа **Combined** (сборка и запуск из Git).
3. Подключает репозиторий `yanteleshko00-commits/vse-proekty-ian`.
4. Для первого теста выбирает ветку `deploy/container-ready`. После проверки и отдельного решения можно использовать `main`.
5. Тип сборки: **Dockerfile**. Путь: `/Dockerfile`. Build context: корень репозитория.
6. Проверяет публичный HTTP-порт **3000**. В Dockerfile он указан через `EXPOSE 3000`; сервер привязан к `0.0.0.0`.
7. На первом этапе оставляет **1 instance**.

## Переменные окружения

Установить:

| Переменная | Значение |
|---|---|
| `NODE_ENV` | `production` |
| `PORT` | `3000` |
| `GENERATION_JOBS_DIR` | `/app/data/generation-jobs` |

В секретные переменные сервиса перенести только те действующие ключи ИИ-провайдеров, которыми владелец проекта вправе пользоваться:

- `GEMINI_API_KEY`
- `OPENROUTER_API_KEY`
- `GROQ_API_KEY`
- `DEEPSEEK_API_KEY`
- `MISTRAL_API_KEY`
- `ANTHROPIC_API_KEY`
- `CLOUDFLARE_ACCOUNT_ID` и `CLOUDFLARE_API_TOKEN`

Дополнительные параметры моделей перечислены в `.env.example`. Не вставлять настоящие ключи в GitHub, PR, README или эту инструкцию. Не включать генерацию изображений, если это отдельно не согласовано.

## Постоянное хранилище

Создать volume с режимом **Single Read/Write** и добавить правило монтирования:

| Поле Northflank | Значение |
|---|---|
| Container mount path | `/app/data/generation-jobs` |
| Volume mount path | Оставить пустым (использовать корень тома) |

Не вводить символ `/` в поле Volume mount path: оно задаёт относительную папку внутри тома, а не абсолютный путь контейнера. Northflank описывает Container mount path как абсолютный путь контейнера, а Volume mount path как необязательную относительную папку тома.

Для Single Read/Write тома сервис ограничен одним экземпляром и не может горизонтально масштабироваться с этим же томом. Для текущего приложения это ожидаемое ограничение: сервер хранит задания в локальном каталоге и использует память процесса для активных задач. Не включать несколько реплик.

Начальный размер для теста: **2 GiB**. Не подключать том ко всему `/app`, чтобы не перекрывать файлы самого приложения. Следует учитывать права доступа к каталогу тома.

После запуска `GET /api/health` должен возвращать:

- `ok: true`
- `generationJobStorage: "persistent-disk-mounted"`
- `generationJobStorageWritable: true`

Если статус отличается, не переключать домен и не считать перенос завершённым.

## Проверка перед переключением домена

1. Убедиться, что в `aiProviders` есть ожидаемые провайдеры. Пустой массив обычно означает, что секретные ключи не перенесены.
2. Создать тестовый проект, дождаться завершения, скачать PPTX и PDF и открыть оба файла.
3. Перезапустить сервис и проверить, что идентификатор завершённой задачи и ссылки на артефакты продолжают работать.
4. Убедиться, что health endpoint показывает подключённый и доступный для записи постоянный том.
5. Только после этого отдельно спланировать DNS и TLS для `vseproekty.com`. Старый Render пока оставить работающим как точку отката.

## Стоимость и ограничения тарифа

По текущей странице тарифов Sandbox указан как бесплатный, без банковской карты, с лимитом до **$20 ресурсов в месяц**, двумя сервисами, двумя jobs и одной базой данных. Northflank прямо указывает, что Sandbox не предназначен для production: https://northflank.com/pricing.

Для ориентировочной оценки:
- compute plan **0.5 vCPU / 1 GB**: **$12/мес.**
- compute plan **1 vCPU / 2 GB**: **$24/мес.**
- persistent NVMe storage: **$0.11657 за GiB в месяц**
- исходящий трафик: **$0.06/GB**

Следовательно, 1 vCPU / 2 GB и диск 2 GiB стоят ориентировочно **$24.23/мес.** до исходящего трафика и применимых налогов. Это расчёт по опубликованным ставкам, не гарантия окончательного счёта. Перед созданием ресурса владелец должен проверить калькулятор и billing summary в аккаунте.
