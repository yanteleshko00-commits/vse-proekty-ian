# Развёртывание на Northflank

Эта инструкция предназначена для взрослого владельца аккаунта и платёжного профиля. Перед регистрацией или оплатой проверьте действующие условия Northflank: https://northflank.com/legal/terms. Нельзя указывать ложную дату рождения или использовать чужие документы.

## Текущая готовность

- Приложение собирается из корневого Dockerfile.
- Контейнер слушает `0.0.0.0:3000`.
- Проверка состояния: `GET /api/health`.
- Каталог заданий и артефактов: `/app/data/generation-jobs`.
- CI собирает образ, запускает контейнер и проверяет health endpoint.
- Эта ветка `deploy/container-ready` предназначена для предварительного теста. Production на Render не затрагивается.

## Создание тестового сервиса

1. Создать проект `vse-proekty-ian`.
2. Создать сервис типа **Combined** (сборка и запуск из Git).
3. Подключить репозиторий `yanteleshko00-commits/vse-proekty-ian`.
4. Для первого теста выбрать ветку `deploy/container-ready`. После проверки и отдельного решения можно использовать `main`.
5. Тип сборки: **Dockerfile**. Путь: `/Dockerfile`. Build context: корень репозитория.
6. Проверить публичный HTTP-порт **3000**. В Dockerfile он уже указан через `EXPOSE 3000`; сервер привязан к `0.0.0.0`.
7. Количество экземпляров: **1** на время использования одного диска Single Read/Write.

## Переменные окружения

Установить:

| Переменная | Значение |
|---|---|
| `NODE_ENV` | `production` |
| `PORT` | `3000` |
| `GENERATION_JOBS_DIR` | `/app/data/generation-jobs` |

В безопасные переменные сервиса перенести только те действующие ключи провайдеров, которые сейчас действительно настроены у владельца в старом хостинге. Приложение поддерживает:

- `GEMINI_API_KEY`
- `OPENROUTER_API_KEY`
- `GROQ_API_KEY`
- `DEEPSEEK_API_KEY`
- `MISTRAL_API_KEY`
- `ANTHROPIC_API_KEY`
- `CLOUDFLARE_ACCOUNT_ID` и `CLOUDFLARE_API_TOKEN`

Дополнительные параметры моделей перечислены в `.env.example`. Не вставлять настоящие ключи в GitHub, PR, README или эту инструкцию. Не включать генерацию изображений, если это отдельно не согласовано.

## Постоянное хранилище

Создать volume с режимом **Single Read/Write** и смонтировать его в контейнер:

```text
Container mount path: /app/data/generation-jobs
Volume mount path:    /
```

Начальный размер можно выбрать 2 GiB и увеличить при необходимости. Не подключать этот Single Read/Write volume к нескольким репликам: Northflank ограничивает сервис с таким томом одним экземпляром. Монтаж именно в каталог заданий, а не в `/app`, чтобы не перекрывать файлы приложения.

После запуска `GET /api/health` должен возвращать:

- `ok: true`
- `generationJobStorage: "persistent-disk-mounted"`
- `generationJobStorageWritable: true`

Если статус отличается, не переключать домен и не считать перенос завершённым.

## Проверка перед переключением домена

1. Убедиться, что в `aiProviders` есть ожидаемые провайдеры. Пустой массив обычно означает, что ключи не перенесены.
2. Создать тестовый проект, дождаться завершения, скачать PPTX и PDF и открыть оба файла.
3. Проверить, что ссылки на скачивание работают после перезапуска сервиса. Для проверки перезапуск должен выполнять владелец сервиса.
4. Убедиться, что health endpoint продолжает показывать подключённый и доступный для записи постоянный том.
5. Только после этого отдельно спланировать DNS и TLS для `vseproekty.com`. Старый Render пока оставить работающим как точку отката.

## Стоимость и ограничения тарифа

Актуальные цены и лимиты нужно проверять перед созданием ресурсов: https://northflank.com/pricing. Бесплатный Sandbox подходит для тестирования, но в документации Northflank отдельно сказано, что бесплатный план не следует использовать для production. Постоянный сервис тарифицируется по вычислительным ресурсам, диску и исходящему трафику.
